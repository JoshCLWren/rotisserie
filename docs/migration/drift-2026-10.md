# Drift inventory — ComicPile snapshot vs. HEAD (2026-10)

This appendix to [`MIGRATION.md`](../../MIGRATION.md) records the drift between
the legacy snapshot preserved under `reference/legacy-factory/` and the live
ComicPile source as of 2026-10-05. It is documentation only: it activates no
workflow, changes no schedule, enables no mutation or canary variable, touches
no secret, and does not modify any file under `reference/legacy-factory/`.

It exists so a later extraction chunk (R2 onward) starts from a verified map of
what changed, what is new, and what is still byte-identical to the archived
baseline, rather than re-deriving it.

## Conventions

- **Dates are UTC.** Every date in this document is the commit's author
  timestamp converted to UTC (`YYYY-MM-DD`), matching what the GitHub REST API
  returns. The ComicPile commits were authored at UTC−05:00, so a commit made
  late in the local evening lands on the next UTC day; dates here can therefore
  be one day later than a `git log` run in the source repository's local
  timezone. The migration snapshot `2dc9b675e1a8` was authored
  `2026-09-25T19:37-05:00`, i.e. **2026-09-26** UTC.
- **Commit SHAs are abbreviated to 12 characters** everywhere in prose and
  tables. The full 40-character SHA for every commit referenced below is listed
  once in [Commit SHA reference](#commit-sha-reference); use that table as the
  collision-resistant anchor when re-verifying.

## Meaningful commits — adopt / adapt / skip

Classification follows the architecture boundaries in `AGENTS.md`. The
`adopt` / `adapt` / `skip` buckets here are a working triage for extraction
effort, not a replacement for the test-enforced taxonomy in
[`MIGRATION_INVENTORY.md`](../../MIGRATION_INVENTORY.md)
(`migrate` / `reference` / `product-specific` / `retire`), which remains
canonical for anything copied under `reference/legacy-factory/`: roughly,
`adopt`/`adapt` map to `migrate`, and `skip` maps to `product-specific` (or
`retire`). Each `adopt` row names the **target layer** its semantics belong to,
so no single directive routes a change to the wrong layer. The inward
dependency rule holds: permission, label, and stage-marker logic lands in the
**adapter**, never in `domain/`.

The recommended ongoing sync strategy is Rotisserie-as-upstream (land generic
semantics in Rotisserie first) backed by a drift-check CI as the guardrail.
None of these chunks enable autonomous execution or external mutation; those
remain gated by the existing kill-switch variable and human approval.

**Workflow-activation gate.** R8 and R10 only *describe candidate* workflows;
they do not pre-approve any workflow. Per `AGENTS.md`, the only active workflows
are `.github/workflows/ci.yml` and the issue-9-only `canary-merge.yml`.
Activating any further workflow — including an R8 drift-check or an R10 release
workflow — requires a separate approved issue that explicitly changes the
boundary. Any such workflow must remain schedule-free, and every active workflow
other than the approved canary must stay read-only. R8 calling itself "the
guardrail" does not exempt it from this gate.
